## 线性结构

### 数组

- **定义**：一段连续存储的相同类型数据元素的序列
- **存储方式**：顺序存储，物理地址连续
- **操作**：随机访问（O(1)）、插入（O(n)）、删除（O(n)）
- **特点**：读快写慢，空间利用率高

**🎯 一句话人话**：数组是一排连着坐的座位，直接喊号就能找到人（O(1)），但要插队就得全员挪（O(n)）。

**💡 类比**：电影院连排座位，知道座位号一步到位；中间加个人，后面的人全得往右挪。

**✍️ 小例子**：a[0..9] 访问 a[5] 一步定位；在 a[0] 处插入新元素，其余 9 个都得后移。

**⚠️ 常见误区**：数组"随机访问 O(1)"指的是按下标取数快；但"插入/删除是 O(n)"，别混成 O(1)。

### 链表

- **单链表**：每个节点含数据域和指针域，只指向后继
- **双链表**：每个节点含前驱指针和后继指针
- **循环链表**：尾节点指针指向头节点，构成环
- **操作复杂度**：
  - 随机访问：O(n)
  - 插入/删除（已知位置）：O(1)
  - 插入/删除（未知位置）：O(n)（需先查找）

**🎯 一句话人话**：链表像手拉手的一串人，只知道邻居是谁；找到人之后拉入/踢出都只要动两下指针（O(1)）。

**💡 类比**：火车车厢靠挂钩连接，拆挂一节车厢只需要动它两边的挂钩。

**✍️ 小例子**：在节点 p 后插 q：`q.next = p.next; p.next = q`——两步 O(1)；但要找 p 得从头遍历，O(n)。

**⚠️ 常见误区**：链表"插入 O(1)"的前提是**已知插入位置**；未知位置要先查找，仍是 O(n)。数组恰好相反（找下标 O(1)、插入 O(n)）。

### 稀疏矩阵

- **定义**：矩阵中多数元素为零，仅存储非零元素
- **三元组表示法**：(行号, 列号, 值)
- **压缩存储**：节省存储空间，便于矩阵运算

**🎯 一句话人话**：矩阵里绝大多数是 0，只记"哪一行哪一列是什么数"这一张清单，省内存。

**💡 类比**：点名册只记到场的人，不来的人不用每人写一遍"不在"。

**✍️ 小例子**：5×5 矩阵只有 3 个非零元素 → 三元组表只存 3 条：(行,列,值)，如 (1,2,9)、(3,3,5)、(4,1,7)。

**⚠️ 常见误区**：三元组只存**非零元素**，不是存所有元素；别把 0 也存进去。

## 栈与队列

### 栈

- **定义**：限定仅在表尾进行插入和删除的线性表（后进先出，LIFO）
- **存储方式**：顺序栈（数组）、链栈（链表）
- **基本操作**：Push（入栈）、Pop（出栈）、Peek（查看栈顶）
- **应用场景**：表达式求值、括号匹配、函数调用栈、递归转非递归

**🎯 一句话人话**：栈是"后进先出"的摞盘子，最后放上去的最先拿走。

**💡 类比**：羽毛球筒/一摞盘子——只能从顶上取、从顶上放。

**✍️ 小例子**：后缀表达式 "3 4 +"：push 3 → push 4 → 遇 + 弹出 4、3 → 3+4=7 → push 7，结果 7。

**⚠️ 常见误区**：栈判"空/满"看栈顶指针；递归转非递归常用栈模拟，但别把队列当栈用（FIFO vs LIFO）。

### 队列

- **定义**：限定在表头删除、表尾插入的线性表（先进先出，FIFO）
- **存储方式**：
  - **顺序队列**：数组实现，存在"假溢出"问题
  - **循环队列**：首尾相连，解决假溢出
  - **链队列**：链表实现
- **基本操作**：Enqueue（入队）、Dequeue（出队）
- **应用场景**：缓冲区、消息队列、广度优先遍历、层次遍历

**🎯 一句话人话**：队列是"先进先出"的排队，先来的先服务。

**💡 类比**：食堂排队打饭——先到先打，后来的排后面。

**✍️ 小例子**：cap=5 顺序队列入队 1、2、3、4、5 → front=0、rear=5，判"满"；再出队两个 → front=2，此时数组前 2 格空着但 rear 已在末尾，无法再入队——这就是假溢出；循环队列让 rear 绕回 0 复用空位。

**⚠️ 常见误区**："假溢出"不是真满，前面空位没用上；循环队列判满用 (rear+1)%cap==front，判空用 front==rear。

### 双端队列（Deque）

- **定义**：允许在两端进行插入和删除的线性表
- **输入受限双端队列**：一端只能插入，另一端可插入删除
- **输出受限双端队列**：一端只能删除，另一端可插入删除

**🎯 一句话人话**：双端队列两头都能进出，比普通队列灵活；限制版是有一头只能进或只能出。

**💡 类比**：双开门通道——两头都能走；输入受限=只有一头能进人；输出受限=只有一头能出人。

**✍️ 小例子**：输入受限双端队列（右端不能插）：想从左边插入可以，想从右边插入不行，两端都能删。

**⚠️ 常见误区**：输入受限≠输出受限。输入受限=某端禁止插入；输出受限=某端禁止删除，别记反。

## 串

### 串的基本操作

- **定义**：由零个或多个字符组成的有限序列
- **存储方式**：定长顺序存储 / 堆分配存储 / 块链存储
- **基本操作**：赋值、连接、求子串、定位（模式匹配）

**🎯 一句话人话**：串就是字符串，考试重点是"在一个长字符串里找子串"（模式匹配）。

**💡 类比**：在整本书里找一句话——一页页翻是暴力匹配，用目录/KMP 更聪明。

**✍️ 小例子**：主串 "ababc" 中找模式 "abc"：暴力从每个位置试，主串第 3 个字符起匹配成功，返回位置 3。

**⚠️ 常见误区**：子串≠子序列：子串必须连续；"定位"即模式匹配，返回首次出现位置。

### KMP算法

- **目的**：高效的模式串匹配算法
- **核心思想**：利用已匹配部分的信息，避免不必要的回溯
- **Next数组**：记录模式串中每个位置的最长公共前后缀长度
- **时间复杂度**：O(n+m)
- **优势**：相比暴力匹配的 O(n×m) 有显著提升

**🎯 一句话人话**：KMP 是"吃了亏不回头"的匹配——失配时主串指针不回退，靠 next 数组跳着继续。

**💡 类比**：查词典找词，翻过的一页不会因为没找到又翻回去；记住刚才翻到哪，接着往后。

**✍️ 小例子**：模式 "abab" 的 next=[-1,0,0,1]（第 4 位前 "aba" 最长公共前后缀 "a" 长度 1）；总时间 O(n+m)，暴力是 O(n×m)。

**⚠️ 常见误区**：next 数组记的是**模式串自身**的前后缀信息，与主串无关；next[j] 不是字符值，是"最长公共前后缀长度"。

## 数组与广义表

### 数组

- **多维数组的存储**：按行优先或按列优先存储
- **行优先（C/Java）**：行下标变化慢，列下标变化快
- **列优先（Fortran）**：列下标变化慢，行下标变化快
- **地址计算**：数组元素地址 = 基地址 + 下标偏移量×元素大小

**🎯 一句话人话**：多维数组排成一行存放，按"行优先"或"列优先"算每个元素在第几格。

**💡 类比**：把 3×4 的座位表按一行行或一列列编号成一条长队，找人就按编号换算座位。

**✍️ 小例子**：3×4 数组按行优先，a[1][2] 的偏移 = 1×4+2 = 6 → 地址 = 基址 + 6×元素大小。

**⚠️ 常见误区**：行优先是"行下标变化慢、列下标变化快"；地址公式别把行列顺序写反（a[1][2] 是 1×列数+2，不是 2×行数+1）。

### 广义表

- **定义**：线性表的推广，表中元素可以是原子也可以是子表
- **表示**：LS = (a₁, a₂, ..., aₙ)，其中每个aᵢ可以是原子或广义表
- **存储方式**：链式存储（头尾链表表示法）
- **深度**：广义表展开后括号嵌套的最大层数
- **长度**：最外层元素个数

**🎯 一句话人话**：广义表是"能装表的表"，重点是分清"长度"（最外层有几个元素）和"深度"（括号套了几层）。

**💡 类比**：文件夹里可以再放文件夹；最外层有几个东西=长度，套了几层=深度。

**✍️ 小例子**：LS=(a,(b,c))：长度 2（a 和 (b,c) 两个最外层元素）；深度 2（外括号+内括号）。

**⚠️ 常见误区**：原子深度按 0 计、子表深度=内部最大深度+1；(a,(b,c)) 长度是 2 不是 3，子表整体算一个元素。

## 树与二叉树（⚠️ 必考重点）

### 二叉树的基本性质

- **性质1**：第i层最多有 2^(i-1) 个节点（i≥1）
- **性质2**：深度为k的二叉树最多有 2^k - 1 个节点（k≥1）
- **性质3**：叶子节点数 n₀ = n₂ + 1（n₂为度为2的节点数）
- **性质4**：具有n个节点的完全二叉树深度 ⌈log₂(n+1)⌉
- **性质5**：完全二叉树节点编号1开始：
  - 节点i的左孩子 = 2i
  - 节点i的右孩子 = 2i+1
  - 节点i的父节点 = ⌊i/2⌋

**🎯 一句话人话**：二叉树的性质就是几条"数节点/算深度"的口诀，套公式就能得分。

**💡 类比**：楼房层数与总户数的关系——第 i 层最多住 2^(i-1) 户，k 层楼最多 2^k-1 户。

**✍️ 小例子**：完全二叉树中节点 i 的左孩子 = 2i：根节点 1 的左孩子 = 2，右孩子 = 3；度为 2 的节点有 3 个时，叶子 n₀ = n₂+1 = 4。

**⚠️ 常见误区**：性质 3 是 n₀ = n₂+1，不是 n₁；完全二叉树编号从 1 开始，孩子 2i/2i+1 只在完全二叉树成立，普通二叉树不适用。

### 二叉树遍历（⚠️ 必考还原）

- **前序遍历**（根-左-右）： NLR
- **中序遍历**（左-根-右）： LNR
- **后序遍历**（左-右-根）： LRN
- **层序遍历**：逐层从左到右
- **遍历还原规则**：
  - ✅ 已知前序+中序 → **唯一确定**二叉树
  - ✅ 已知后序+中序 → **唯一确定**二叉树
  - ❌ 已知前序+后序 → **不能唯一确定**（存在多解）

**🎯 一句话人话**：遍历就是按固定顺序"逛"二叉树；给两种遍历能反推出树，关键靠"中序分左右"。

**💡 类比**：前序告诉谁当根，中序告诉根的左边有谁、右边有谁——两者一凑，树就画出来了。

**✍️ 小例子**：前序 ABDCE、中序 DBAEC：前序首个 A=根，中序以 A 分列 → 左子树 DB、右子树 EC（还原步骤见上方口诀）。

**⚠️ 常见误区**：前序+后序**不能**唯一还原（只知道根、分不出左右）；"前序找根、中序分列"是还原唯一铁律。

- ⚠️ 必考行：前序+中序（或后序+中序）唯一确定二叉树，前序+后序不能；NLR/LNR/LRN 顺序必背。

::: tip 还原口诀
前序找根（第一个）→ 中序分列（根左右）→ 左右子树递归还原
:::

### 二叉排序树（BST）

- **定义**：左子树所有节点值 < 根节点值 < 右子树所有节点值
- **中序遍历结果**：有序序列（升序）
- **查找效率**：平均 O(log n)，最坏 O(n)（退化为链表）

**🎯 一句话人话**：BST 是"左小右大"的树，中序遍历就得到从小到大排好序的序列。

**💡 类比**：字典按字母排，每次比较都能排除一半——像二分查找的树形版。

**✍️ 小例子**：依次插入 5、3、8、1：根 5，左子树 3（左 1）、右子树 8；中序遍历 = 1,3,5,8 升序 ✓。

**⚠️ 常见误区**：BST 不保证平衡——按 1,2,3,4 顺序插入会退化成链表，查找变 O(n)；这是引出 AVL 的原因。

### 平衡二叉树（AVL树）

- **定义**：任意节点的左右子树高度差不超过1（平衡因子 ∈ {-1, 0, 1}）
- **目的**：保证操作复杂度为 O(log n)
- **失衡类型**：
  - LL型：左子树的左子树插入 → 右旋
  - RR型：右子树的右子树插入 → 左旋
  - LR型：左子树的右子树插入 → 先左旋再右旋
  - RL型：右子树的左子树插入 → 先右旋再左旋

**🎯 一句话人话**：AVL 让树保持"左右高度差不超过 1"，插入后不平衡就旋转救回来。

**💡 类比**：玩跷跷板，一边太重就转一下让两边平衡；LL/RR 转一次，LR/RL 转两次。

**✍️ 小例子**：依次插入 3、2、1 → 节点 3 失衡（LL 型）→ 右旋：2 变根，1 在左、3 在右。

**⚠️ 常见误区**：LR 型（左子树的**右**子树引起）要**先左旋再右旋**，RL 型先右旋再左旋；四种类型名称说的是"破坏点在哪"，别记反。

### 哈夫曼树（⚠️ 必考计算）

- **定义**：带权路径长度（WPL）最小的二叉树
- **构建方法**：贪心算法，每次选取最小权值的两棵树合并
- **公式**：`WPL = Σ(Wi × Li)`（Wi=叶子权值, Li=路径长度）
- **哈夫曼编码**：前缀编码（任一字符编码不是另一字符编码的前缀）
- **特点**：n个叶子节点 → 共 2n-1 个节点，没有度为1的节点

::: warning 哈夫曼树计算技巧
每次取最后开始合并！权值：{2,3,5,7} → 先合并 2+3=5 → 再合并 5+5=10 → 最后合并 7+10=17 → WPL = 2×3 + 3×3 + 5×2 + 7×1 = 34
:::

**🎯 一句话人话**：哈夫曼树让"出现频率高的字符路径最短"，总带权路径长度 WPL 最小。

**💡 类比**：常用字放键盘中央、生僻字放角落——用得多的离手近，整体最省力。

**✍️ 小例子**：最小两权合并的贪心过程见上方 callout 案例（{2,3,5,7} 依次合并 5、10、17）；结论背熟：n 个叶子 → 共 2n-1 个节点、无度为 1 的节点。

**⚠️ 常见误区**：哈夫曼树**无度为 1 的节点**；哈夫曼编码是前缀编码（任一编码不是另一编码的前缀），可无歧义解码。

- ⚠️ 必考行：WPL=Σ(叶子权×路径长)，贪心每次合并最小两权；n 叶→2n-1 节点、无度 1 节点。

### 树与森林的转换

- **森林转二叉树**：兄弟相连，父节点保留最左孩子的链接
- **二叉树转森林**：左分支恢复原树，右分支恢复原兄弟

**🎯 一句话人话**：森林和二叉树能互相转换：转过去"兄弟变右孩子"，转回来"右孩子还原成兄弟"。

**💡 类比**：把一排树用"最左孩子+右边兄弟"的规则串成一棵二叉树，像把多列队伍合成一列。

**✍️ 小例子**：3 棵树组成的森林 → 根 A、B、C 用右指针串成链：A 的右孩子=B、B 的右孩子=C。

**⚠️ 常见误区**：森林转二叉树是"兄弟相连、根连右链"；转回森林时，根节点只有左孩子算一株原树，右边一路都是兄弟树。

## 图（⚠️ 遍历 + 最小生成树 + 最短路径）

### 图的存储

| 存储方式 | 空间复杂度 | 适用场景 | 查找边 |
|---------|-----------|---------|--------|
| 邻接矩阵 | O(n²) | 稠密图 | O(1) |
| 邻接表 | O(n+e) | 稀疏图 | O(e) |

**🎯 一句话人话**：存图就两种主流方式：矩阵"以空间换时间"、邻接表"以时间省空间"。

**💡 类比**：邻接矩阵像全员点名册（每人记所有人）；邻接表像通讯录（只记认识的人）。

**✍️ 小例子**：4 顶点稀疏图：邻接矩阵要 4×4=16 格；邻接表只存真实存在的边，约 O(n+e)。

**⚠️ 常见误区**：稠密图用邻接矩阵、稀疏图用邻接表；查边：矩阵 O(1)，邻接表 O(e)，别把适用场景记反。

### 图的遍历

| 遍历方式 | 实现 | 时间复杂度 | 应用 |
|---------|------|-----------|------|
| 深度优先 DFS | 栈/递归 | O(n+e) | 连通性、拓扑排序 |
| 广度优先 BFS | 队列 | O(n+e) | 最短路径(无权)、层次遍历 |

**🎯 一句话人话**：DFS 一条道走到黑再回头（用栈），BFS 一层层往外扩散（用队列）。

**💡 类比**：DFS 像走迷宫先死磕一条路；BFS 像水波一圈圈荡开。

**✍️ 小例子**：从 A 出发 BFS：先访问 A 的所有邻居，再访问邻居的邻居，逐层推进，正好配合队列的 FIFO。

**⚠️ 常见误区**：DFS 用栈/递归、BFS 用队列；两者时间都是 O(n+e)，区别只在"深度优先"还是"广度优先"。BFS 可用于无权图最短路径。

### 最小生成树

| 算法 | 策略 | 时间复杂度 | 适用 |
|------|------|-----------|------|
| **Prim** | 加点法（选与已选集合连接的最小边） | O(n²) | 稠密图 |
| **Kruskal** | 加边法（按权排序，不形成环） | O(e log e) | 稀疏图 |

**🎯 一句话人话**：最小生成树是"连通所有点且总边权最小"的树；Prim 加点、Kruskal 加边。

**💡 类比**：修路连通各村——Prim 从已通村往外修最近的；Kruskal 把每条路按造价排序，便宜的先修、不修成环。

**✍️ 小例子**：边权排序后从最小开始选：1、2、3…，只要不构成环就收下，直到连成 n-1 条边（n 个顶点）。

**⚠️ 常见误区**：Kruskal 的关键是"不能成环"（用并查集判），不是看到小边就无脑收；Prim O(n²) 适稠密、Kruskal O(e log e) 适稀疏。

### 最短路径

| 算法 | 类型 | 能否负权 | 时间复杂度 |
|------|------|---------|-----------|
| **Dijkstra** | 单源 | ❌ 不能 | O(n²) |
| **Floyd** | 多源 | ✅ 能(无负环) | O(n³) |
| **Bellman-Ford** | 单源 | ✅ 能，可检负环 | O(ne) |

**🎯 一句话人话**：Dijkstra 求"一个点到所有点"的最短，Floyd 求"任意两点间"的最短；Dijkstra 怕负权。

**💡 类比**：Dijkstra 像每次先处理离你最近的邻居；Floyd 像三层循环挨个尝试"绕一下会不会更近"。

**✍️ 小例子**：A→B=1、A→C=5、B→C=2、C→D=1：Dijkstra 得 A→C=3（经 B）、A→D=4（经 B→C→D）；Floyd 同样能得到任意两点最短距。

**⚠️ 常见误区**：Dijkstra **不能**处理负权（贪心假设被负权破坏），负权用 Bellman-Ford 或 Floyd；Floyd O(n³)，Dijkstra O(n²)。

- ⚠️ 必考行：Dijkstra 单源、无负权、O(n²)，贪心每次选距离最近的未确定顶点。

### 拓扑排序

- **适用**：有向无环图（DAG）
- **算法**：反复选入度为0的顶点输出 → 删除其出边 → 重复
- **判定环**：输出顶点数 < 总顶点数 → 存在环

**🎯 一句话人话**：拓扑排序把有依赖关系的任务排成先后顺序；每次先做"没人依赖它"的事。

**💡 类比**：大学选课——先修课入度低先上，学完把"依赖它"的课的入度减一。

**✍️ 小例子**：A(无先修)→B→C：输出 A、删 A 的出边后 B 入度变 0 → 输出 B → 再输出 C → 拓扑序 A,B,C。

**⚠️ 常见误区**：拓扑排序只能用于 DAG（有向无环图）；若输出的顶点数 < 总顶点数，说明图里有环，排不完。

### 关键路径（⚠️ 必考计算）

- **前提**：AOE网（边=活动，顶点=事件）
- **概念**：最长路径长度 = 工程最短完成时间
- **计算公式**：
  - `Ve(j) = max{Ve[i] + weight(i,j)}`（正向，最早开始）
  - `Vl(i) = min{Vl[j] - weight(i,j)}`（反向，最迟开始）
  - `关键活动`：Ve(i) == Vl(i)

**🎯 一句话人话**：关键路径是工程里"最不能拖"的那条最长路，它决定整个工程最短工期。

**💡 类比**：几条流水线并行，最慢的那条决定了总完工时间，它上面每个环节都不能延误。

**✍️ 小例子**：活动 1→2=2、2→3=3、1→3=5、3→4=1：Ve(1)=0、Ve(2)=2、Ve(3)=max(2+3,0+5)=5、Ve(4)=6；反向 Vl(3)=5、Vl(2)=2；Ve==Vl 的边是关键活动 → 关键路径长 6，即最短工期。

**⚠️ 常见误区**：Ve 正向取 **max**、Vl 反向取 **min**，方向取反就错；关键活动是 Ve(i)==Vl(i) 的边，路径上全是要害环节。

- ⚠️ 必考行：关键路径=最长路径=最短工期；Ve 正向取 max、Vl 反向取 min，Ve=Vl 的边为关键活动。

## 查找算法

| 查找方式 | 前提 | 时间复杂度 | 特点 |
|---------|------|-----------|------|
| 顺序查找 | 无 | O(n) | 最简单 |
| **二分查找** | **有序** | **O(log n)** | 前提有序，考最多 |
| 分块查找 | 块间有序 | O(√n) | 折中方案 |
| 散列查找 | 哈希表 | O(1) 平均 | 设计哈希函数 |

### 哈希冲突处理

- **开放定址法**：线性探测/平方探测
- **链地址法（拉链法）**：同义词链表链接 → **最常用**
- **装填因子** α = n/m，越小冲突越少

**🎯 一句话人话**：哈希函数把不同数据算到同一格就叫"冲突"，解决冲突最常考"链地址法"。

**💡 类比**：快递柜一个格子塞了两件快递——链地址法就是同一格里挂个"串串"，一件挂一件往下链。

**✍️ 小例子**：表长 m=7、已装 n=5 个元素，装填因子 α=n/m=5/7≈0.71；α 越大冲突越频繁，α 越小越稀疏。

**⚠️ 常见误区**：链地址法把同义词链成一串（最常用）；开放定址法是往后找空位（线性/平方探测）；装填因子 α=n/m，别把分子分母记反。

## 算法设计与分析

| 算法思想 | 核心特征 | 典型问题 |
|---------|---------|---------|
| **贪心** | 每步局部最优 | 哈夫曼、Prim/Kruskal、Dijkstra |
| **动态规划** | 最优子结构+重叠子问题+状态转移 | LCS、背包、Floyd |
| **分治** | 分解→递归→合并 | 归并排序、快排、二分 |
| **递归** | 自调用+递归基 | 二分查找、树遍历、Hanoi |

**🎯 一句话人话**：四种算法思想一句话——贪心选当下最好、DP 记重复子问题的答案、分治拆小了再合、递归自己调自己。

**💡 类比**：贪心像点菜只点最想吃的；DP 像做笔记避免重复计算；分治像把大扫除分给小组再汇总；递归像俄罗斯套娃。

**✍️ 小例子**：归并排序=分治（拆→排→合）；斐波那契=递归/DP；Dijkstra、哈夫曼=贪心；Floyd、LCS、背包=动态规划。

**⚠️ 常见误区**：贪心不一定全局最优（只保证局部），DP 需要"最优子结构+重叠子问题"；分治与 DP 的区别在于子问题是否重叠。

## 📊 跨题对比表（⚠️ 必考）

### 排序算法完整对比

| 排序算法 | 平均时间 | 最坏时间 | 最好时间 | 空间 | 稳定性 | 适用场景 |
|---------|---------|---------|---------|------|--------|---------|
| 冒泡排序 | O(n²) | O(n²) | O(n) | O(1) | ✅ 稳定 | 小数据/教学 |
| 直接选择 | O(n²) | O(n²) | O(n²) | O(1) | ❌ 不稳定 | 小数据 |
| 直接插入 | O(n²) | O(n²) | O(n) | O(1) | ✅ 稳定 | **近乎有序数据** |
| **快速排序** | O(n log n) | O(n²) | O(n log n) | O(log n) | ❌ 不稳定 | **通用首选** |
| 堆排序 | O(n log n) | O(n log n) | O(n log n) | O(1) | ❌ 不稳定 | 内存受限 |
| **归并排序** | O(n log n) | O(n log n) | O(n log n) | O(n) | ✅ 稳定 | **需要稳定时** |
| 基数排序 | O(d(n+r)) | O(d(n+r)) | O(d(n+r)) | O(n+r) | ✅ 稳定 | 整数/定长字符串 |

**🎯 一句话人话**：排序就盯三件事——稳不稳定、时间复杂度、空间复杂度；考试就考这张对比表。

**💡 类比**：稳定排序像"先来后到排队"，值相等也按原顺序站；不稳定会插队，相等元素顺序被打乱。

**✍️ 小例子**：对 [3a,3b,1] 排序（3a、3b 值相同）：稳定排序保持 3a 在 3b 前；快排/选择等不稳定排序可能把 3b 换到 3a 前。

**⚠️ 常见误区**：堆排序属于"选择类"但**不稳定**，别以为选择类都不稳定；归并稳定但空间 O(n)，快排空间 O(log n)。

- ⚠️ 必考行：稳定性口诀——冒/插/归/基稳，选/快/堆不稳。
- ⚠️ 必考行：快排平均 O(n log n)、最坏 O(n²)、不稳定、空间 O(log n)。

::: tip 排序口诀
"选堆归基不挑数据，**快排平均最常用**；需要稳定用**归并**，空间紧张选**堆排**"
:::

### 二叉树遍历还原对照

| 已知组合 | 能否还原 | 理由 |
|---------|---------|------|
| 前序 + 中序 | ✅ **能** | 前序定根，中序分列 |
| 后序 + 中序 | ✅ **能** | 后序定根，中序分列 |
| 前序 + 后序 | ❌ **不能** | 仅知根无法分左右（多解） |
| 仅前序 | ❌ **不能** | 信息不足 |

### 查找算法对比

| 算法 | 前提 | 时间 | 适用 |
|------|------|------|------|
| 顺序查找 | 无 | O(n) | 任何表 |
| **二分查找** | **有序** | **O(log n)** | 顺序存储有序表 |
| 哈希查找 | 哈希表 | O(1) 平均 | 快速查找 |
| 分块查找 | 块间有序 | O(√n) | 折中方案 |

**🎯 一句话人话**：查找就三种套路——挨个看（O(n)）、一半一半砍（O(log n)）、记位置直达（O(1)）。

**💡 类比**：顺序查找像在一堆纸里翻；二分像猜数字每次砍半；哈希像存快递柜，按号直接开箱。

**✍️ 小例子**：有序数组 [1,3,5,7,9] 用二分找 7：取中 5 → 7>5 去右半 [7,9] → 找到，约 2 次比较（log₂5≈2.3）。

**⚠️ 常见误区**：二分查找**前提必须有序**，且需顺序存储（能随机访问）；分块查找是块间有序、块内无序的折中。
