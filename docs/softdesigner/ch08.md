> 本章讲的是**信息安全**：数据怎么加密、怎么证明"这是我发的"、网络大门怎么把坏人挡在外面。软设考试里它是性价比很高的一章——不用写代码，全是概念题，把"钥匙怎么分、签名怎么盖、防火墙分几层"三件事记住就能拿分。

**人话概述**：这一章就是"给数据上保险"的说明书——先讲安全底线 CIA（保密/完整/可用）和网络分层（安全基础）；再看加密技术：对称加密像一把钥匙锁门，非对称加密像公共信箱+私钥，实际干活时两个配合着用（混合加密）；接着是哈希与数字签名——给内容"盖私章"，谁都能验、只有你能盖；然后是防火墙、IDS、VPN 这些"网络保安装备"；最后认识常见攻击（SQL 注入、XSS、DDoS）怎么防，以及访问控制（DAC/MAC/RBAC）。

**生活联系**：微信/支付宝转账的"已加密"、网上银行的"安全证书"、公司电脑装的防火墙——全是本章的机制。浏览器地址栏的 HTTPS 小锁头 = 混合加密 + 数字证书；下载软件时对照的 MD5/SHA-256 校验值就是哈希。

**学完会什么**：能分清对称/非对称加密（谁快谁慢、谁管密钥分发、谁支持签名）；能背出"私钥签名、公钥验证"和"公钥加密、私钥解密"两个方向；记得哈希长度（MD5=128 位、SHA-1=160 位、SHA-256=256 位）；能配对攻击与防护（SQL 注入→参数化查询）和说出防火墙三档（包过滤→状态检测→应用代理）谁最快、谁最安全。

**难点预告**：① 对称 vs 非对称的方向特别容易记反——记住"签名用私钥、验证用公钥；加密反着来"的口诀；② 数字签名为什么要"先哈希再签名"、多这一步有什么用；③ 防火墙四类型的工作层（网络层/传输层/会话层/应用层）与"最快 vs 最安全"的对立关系。这三块都是必考，别跳过。

## 安全基础

### CIA 三要素
| 要素 | 含义 |
|------|------|
| **C**onfidentiality | 保密性：未经授权不可读 |
| **I**ntegrity | 完整性：未经授权不可改 |
| **A**vailability | 可用性：授权后可正常访问 |

::: info
**🎯 一句话人话**：信息安全的三条底线——读不了（保密）、改不了（完整）、用得了（可用），丢任何一条都算出事。
:::

::: tip
**💡 类比**：快递柜——只有你的钥匙能开箱（保密）；箱子被人撬开换过货却看不出来（破坏完整）；柜子整体瘫痪取不了件（失去可用）。
:::

::: details ✍️ 小例子
**✍️ 小例子**：文件加密=保保密性；报文被中间人篡改但校验和通不过=破坏完整性；DDoS 把服务器打崩=破坏可用性。
:::

::: warning
**⚠️ 常见误区**：保密性和完整性常混——加密保的是"读不到"（保密），校验和/哈希保的是"改不掉"（完整），两者不是一回事。
:::

### OSI 七层 vs TCP/IP 四层
| OSI | TCP/IP |
|-----|--------|
| 应用层 · 表示层 · 会话层 | 应用层 |
| 传输层 | 传输层 |
| 网络层 | 网际层 |
| 数据链路层 · 物理层 | 网络接口层 |

::: info
**🎯 一句话人话**：网络分层就是把"发数据"拆成几层各管一段；七层是教科书标准，四层是实际用的简化版。
:::

::: tip
**💡 类比**：寄快递——你只管写地址（应用层），分拣中心（传输层）、路线规划（网络层）、实际运送（网络接口层）各司其职。
:::

::: details ✍️ 小例子
**✍️ 小例子**：上层三层（应用/表示/会话）归并成 TCP/IP 的应用层；数据链路层+物理层合并成网络接口层；中间的传输层、网络层一一对应。
:::

::: warning
**⚠️ 常见误区**：别把表示层、会话层硬塞进 TCP/IP——四层模型只有应用/传输/网际/网络接口四层；后面防火墙"包过滤=网络层、代理=应用层"就是按这套层定位的。
:::

## 加密技术（⚠️ 必考对比）

| 对比项 | 对称加密 | 非对称加密 |
|--------|---------|-----------|
| 密钥 | 加密=解密（同一密钥） | 加密≠解密（公钥+私钥） |
| 速度 | 快 | 慢 |
| 用途 | 大量数据加密 | 密钥交换 + 数字签名 |
| 密钥分发 | 困难（需安全通道） | 简单（公钥公开） |
| 代表 | DES/3DES/AES | RSA/ECC |

### 对称加密算法

| 算法 | 密钥长度 | 状态 |
|------|---------|------|
| DES | 56 位 | ❌ 已不安全 |
| 3DES | 112/168 位 | ⚠️ 过渡 |
| **AES** | 128/192/256 位 | ✅ 现行标准 |
| IDEA | 128 位 | PGP 中使用 |

::: info
**🎯 一句话人话**：对称加密就一把钥匙，加解密都用它；考试只记"谁还安全、密钥多少位"。
:::

::: tip
**💡 类比**：一把家门钥匙，锁门开门同一把——快，但钥匙得先安全送到对方手里。
:::

::: details ✍️ 小例子
**✍️ 小例子**：AES-128 = 128 位 = 16 字节（128÷8）；DES 只有 56 位早被穷举攻破，3DES 112/168 位是过渡，AES 128/192/256 位才是现行标准。
:::

::: warning
**⚠️ 常见误区**：DES 的"56 位"别记成 64 位（实际密钥 56 位、另 8 位作校验）；3DES 只是过渡，不是"最新最安全"，现行标准是 AES。
:::

### 非对称加密算法

| 算法 | 基于 | 用途 |
|------|------|------|
| **RSA** | 大数分解 | 加密+签名（最广泛） |
| **ECC** | 椭圆曲线 | 密钥短效率高 |
| Diffie-Hellman | 离散对数 | 密钥交换 |
| DSA | 离散对数 | 数字签名专用 |

::: info
**🎯 一句话人话**：非对称加密是一对钥匙——公钥随便发、私钥自己藏；一个加密、另一个解密。
:::

::: tip
**💡 类比**：公共信箱——任何人都能投信（公钥加密），但只有你手里的钥匙能打开（私钥解密）。
:::

::: details ✍️ 小例子
**✍️ 小例子**：RSA 靠大数分解（33=3×11 好算，反推 3、11 难）；ECC 用椭圆曲线，256 位 ECC ≈ 3072 位 RSA 的安全强度，密钥更短；DH、DSA 都基于离散对数，DSA 专用于签名。
:::

::: warning
**⚠️ 常见误区**：DH/DSA 都基于离散对数，但 DSA 只签名不加密；ECC 的优势是"密钥短、效率高"，不是安全性碾压 RSA——是同等级更省资源。
:::

### 混合加密（实际方案）

```
1. 发送方：生成随机对称密钥 K
2. 用接收方公钥加密 K → 传给接收方
3. 用 K 加密实际数据 → 传给接收方
4. 接收方：用私钥解出 K → 用 K 解密数据
```

::: tip 为什么用混合？
非对称慢但方便传密钥 → 传密钥用非对称
对称快但不能安全传密钥 → 加密数据用对称
:::

::: info
**🎯 一句话人话**：混合加密 = 用非对称安全地送钥匙，再用对称钥匙快速加密正文——两头好处都占。
:::

::: tip
**💡 类比**：先花大钱用保险柜把家里钥匙送过去，之后每次开门都用那把普通钥匙（对称），又快又安全。
:::

::: details ✍️ 小例子
**✍️ 小例子**：流程见上方 code 与 callout：随机生成 K → 公钥加密 K → K 加密数据 → 接收方私钥解 K → K 解密数据（HTTPS 握手就是这套）。
:::

::: warning
**⚠️ 常见误区**：不是"两层都加密数据"——非对称只加密会话密钥 K，真正的大数据用对称加密；别用对称加密传 K（那就又回到密钥分发难题）。
:::

::: danger ⚠️ 必考行
混合加密=非对称传密钥 + 对称加密数据，HTTPS/SSL 就是这一套。
:::

## 哈希函数与数字签名

### 哈希算法

| 算法 | 输出 | 安全状态 |
|------|------|---------|
| MD5 | 128 位 | ❌ 已碰撞 |
| SHA-1 | 160 位 | ❌ 已不安全 |
| **SHA-256** | 256 位 | ✅ 常用 |
| SHA-3 | 可变 | ✅ 最新 |

### 数字签名流程（⚠️ 必考）

```
签名：私钥加密(Hash(消息))
验证：Hash(消息) == 公钥解密(签名)
```

::: tip 数字签名 ≠ 加密
签名用**私钥**（证明身份），验证用**公钥**（任何人可验证）
加密用**公钥**（只有私钥持有者可读），解密用**私钥**
:::

::: info
**🎯 一句话人话**：数字签名 = 拿私钥给"内容的指纹"盖章；谁都能用公钥验章，但只有你有私钥能盖——防篡改、防抵赖。
:::

::: tip
**💡 类比**：亲笔签名——任何人拿你的签名样本都能核对（公钥验证），但别人伪造不出来（私钥唯一）。
:::

::: details ✍️ 小例子
**✍️ 小例子**：对消息 M 哈希得 H（如 SHA-256 256 位）→ 私钥加密 H 得签名 S → 接收方公钥解 S 得 H'，H'==H 则通过（签名≠加密见上方 callout）。
:::

::: warning
**⚠️ 常见误区**：签名是"私钥签、公钥验"，加密是"公钥加密、私钥解"——方向恰好相反；签名的目的是身份+完整+防抵赖，不是保密。
:::

::: danger ⚠️ 必考行
数字签名=私钥签 + 公钥验（先哈希再签名），作用是防篡改、防抵赖；加密才是公钥加密+私钥解密。
:::

### PKI 三要素
- **CA**（证书颁发机构）：签发和管理证书
- **证书**：绑定公钥和身份
- **CRL**（证书撤销列表）：已失效证书清单

::: info
**🎯 一句话人话**：PKI 就是"给公钥办身份证"的体系——CA 发证、证书绑定身份、CRL 记废证。
:::

::: tip
**💡 类比**：公安局办身份证（CA 签发证书），证件把"人脸↔姓名"绑在一起（公钥↔身份），挂失作废就进名单（CRL）。
:::

::: details ✍️ 小例子
**✍️ 小例子**：访问 https 网站，浏览器先验证书是否由可信 CA 签发、是否有效，再决定要不要建立加密连接。
:::

::: warning
**⚠️ 常见误区**：CA 是"信任起点"（根证书），不是加密算法；CRL 是"撤销列表"，别和证书有效期混——证书过期≠进 CRL。
:::

## 网络安全技术

### 防火墙类型

| 类型 | 工作层 | 特点 |
|------|--------|------|
| 包过滤 | 网络层 | 基于 IP/端口，**最快**但最弱 |
| 状态检测 | 传输层 | 跟踪连接状态，较安全 |
| 应用代理 | 应用层 | **最安全**但最慢 |
| 电路网关 | 会话层 | 验证 TCP/UDP 连接 |

### IDS 检测方式

| 方式 | 原理 | 优劣 |
|------|------|------|
| **误用检测（特征）** | 匹配已知攻击模式 | 误报低，漏报高（无法检新攻击） |
| **异常检测** | 偏离正常行为则报警 | 可检新攻击，误报高 |

::: info
**🎯 一句话人话**：IDS 盯着网络找坏人——一条路认老面孔（误用/特征），一条路看新异动（异常）。
:::

::: tip
**💡 类比**：误用检测像按通缉令认脸（只认识已知逃犯）；异常检测像保安发现"你平时不加班、今晚却在办公室"这种反常（新招也可能被逮）。
:::

::: details ✍️ 小例子
**✍️ 小例子**：病毒库匹配已知样本=误用检测（漏报新变种）；凌晨 3 点出现批量登录=异常检测（能报新攻击但日常误报多）。
:::

::: warning
**⚠️ 常见误区**：误用检测"误报低、漏报高"（检不出新攻击）；异常检测"漏报低、误报高"——两个指标的"高/低"别记反。
:::

### VPN 协议
| 协议 | 特点 |
|------|------|
| PPTP | 微软，较老 |
| L2TP | 常与 IPSec 结合 |
| **IPSec** | 网络层标准 |
| SSL/TLS VPN | 应用层，浏览器即用 |
| OpenVPN | 开源，灵活 |

::: info
**🎯 一句话人话**：VPN 是在公网上挖一条"加密隧道"，让远程访问像在内网一样；区别在协议工作在第几层。
:::

::: tip
**💡 类比**：给专用车开一条封闭通道，外面看不见车里装的啥（加密）、也进不来。
:::

::: details ✍️ 小例子
**✍️ 小例子**：IPSec 工作在网络层，站点互联标准；SSL/TLS VPN 工作在应用层，浏览器即用、无需装客户端；OpenVPN 开源灵活、常跑在 UDP 443。
:::

::: warning
**⚠️ 常见误区**：IPSec=网络层，SSL VPN=应用层，层数别记反；L2TP 本身不加密、常与 IPSec 结合（L2TP over IPSec）才安全。
:::

## 网络攻击与防护

| 攻击 | 描述 | 防护 |
|------|------|------|
| DoS/DDoS | 耗尽资源 | 防火墙、流量清洗、CDN |
| SQL 注入 | 注入恶意 SQL | 参数化查询、输入过滤 |
| XSS | 注入恶意脚本 | 输入过滤、输出编码 |
| CSRF | 伪造用户请求 | 令牌验证、Referer 检查 |
| 中间人 | 拦截通信 | TLS 加密、证书验证 |
| 缓冲区溢出 | 利用程序漏洞 | 输入验证、内存保护 |

## 📊 跨题对比表（⚠️ 必考）

### 加密算法完整对比

| 维度 | 对称加密 | 非对称加密 |
|------|---------|-----------|
| 密钥关系 | 加密 = **解密**（同一密钥） | 加密 ≠ 解密（公钥 + 私钥） |
| 速度 | **快** | 慢 |
| 密钥数量 | 1 个 | 1 对（公钥公开，私钥保密） |
| 密钥分发 | **困难**（需安全通道） | 简单（公钥可公开） |
| 数字签名 | ❌ 不支持 | ✅ 支持（私钥签，公钥验） |
| 代表算法 | DES / 3DES / **AES** | **RSA** / ECC / DH |
| 用途 | 大量数据加密 | 密钥交换 + 数字签名 |

::: info
**🎯 一句话人话**：对称快但传密钥难，非对称慢但公钥可公开——所以实战是两个配合着用。
:::

::: tip
**💡 类比**：对称像用同一把钥匙的暗号信，快但钥匙怎么送过去是大问题；非对称像公共信箱+私钥，安全但每封都开信箱很慢。
:::

::: details ✍️ 小例子
**✍️ 小例子**：RSA 实例：p=3、q=11 → n=33、φ=20；取 e=3、d=7（3×7=21≡1 mod 20）；加密 m=5 → 5³=125≡26 (mod 33)；解密 26⁷≡5 ✓。非对称能数字签名（私钥签公钥验），对称不行。
:::

::: warning
**⚠️ 常见误区**：方向别记反——"公钥加密、私钥解密"是保密；"私钥签名、公钥验证"是签名。混用就全错。
:::

::: danger ⚠️ 必考行
对称=同钥快、加密数据；非对称=公钥+私钥、慢、管密钥分发+数字签名；AES 代表对称、RSA 代表非对称。
:::

### 哈希算法输出长度速查

| 算法 | 输出长度 | 安全状态 |
|------|---------|---------|
| MD5 | 128 位 | ❌ 已碰撞 |
| SHA-1 | 160 位 | ❌ 已不安全 |
| **SHA-256** | 256 位 | ✅ 最常用 |
| SHA-384 | 384 位 | ✅ |
| SHA-512 | 512 位 | ✅ |
| SHA-3 | 可变 | ✅ 最新标准 |

::: info
**🎯 一句话人话**：哈希把任意内容"压"成固定长度的数字指纹，长度由算法定；考题就考每个算法输出多少位。
:::

::: tip
**💡 类比**：每个人的身份证号都是定长的；内容变一点、指纹全变（雪崩效应），所以能用来验"有没有被改"。
:::

::: details ✍️ 小例子
**✍️ 小例子**：MD5=128 位（32 个 hex，128÷4）；SHA-1=160 位（40 个 hex）；SHA-256=256 位（64 个 hex）；SHA-512=512 位（128 个 hex）——位数÷4=十六进制字符数 ✓。
:::

::: warning
**⚠️ 常见误区**：MD5 和 SHA-1 都已发现碰撞、不安全；输出长度单位是"位"，MD5 128 位=16 字节，别把位当字节。
:::

::: danger ⚠️ 必考行
MD5=128 位（已碰撞）、SHA-1=160 位（不安全）、SHA-256=256 位（最常用）、SHA-512=512 位。
:::

### 防火墙类型

| 类型 | 工作层 | 速度 | 安全性 |
|------|--------|------|--------|
| 包过滤 | 网络层 | **最快** | 最弱 |
| 状态检测 | 传输层 | 快 | 较安全 |
| **应用代理** | 应用层 | **最慢** | **最安全** |
| 电路网关 | 会话层 | 中 | 中 |

::: info
**🎯 一句话人话**：防火墙是网络门口的查证保安；查得越深越安全、也越慢——从包过滤到应用代理，一层比一层严。
:::

::: tip
**💡 类比**：包过滤只看快递单（IP/端口）；状态检测还看"是不是刚才那单的回单"（连接状态）；应用代理要把包裹打开检查内容（应用层），最安全也最慢。
:::

::: details ✍️ 小例子
**✍️ 小例子**：封外部访问内网 8080 端口→包过滤（网络层）；跟踪 TCP 三次握手判断连接是否合法→状态检测（传输层）；代理代用户访问外网并审查内容→应用代理（应用层）。
:::

::: warning
**⚠️ 常见误区**：别以为"包过滤最安全"——它最快但最弱；应用代理最安全但最慢；电路网关工作在会话层（验证 TCP/UDP 连接），别漏。
:::

::: danger ⚠️ 必考行
包过滤=网络层最快最弱，状态检测=传输层，应用代理=应用层最慢最安全。
:::

### 访问控制

| 模型 | 决策者 | 严格度 | 适用 |
|------|--------|--------|------|
| DAC（自主） | 资源所有者 | 松 | 文件共享 |
| MAC（强制） | 管理员（安全级） | **最严** | 军事/政府 |
| **RBAC（角色）** | 角色权限分配 | 中 | **企业常用** |

::: info
**🎯 一句话人话**：访问控制就是"谁能动这个资源"由谁说了算——DAC 资源主人说了算、MAC 上级强制定、RBAC 按角色分工。
:::

::: tip
**💡 类比**：DAC 像自己家门自己定谁进（灵活）；MAC 像军事区由司令统一分级（严格）；RBAC 像公司按"经理/员工"职位发权限（企业标配）。
:::

::: details ✍️ 小例子
**✍️ 小例子**：Linux `chmod` 由属主授权=DAC；涉密文件按"绝密/机密/秘密"级别访问=MAC；公司给"财务角色"分配报表权限、谁挂这角色谁就有=RBAC。
:::

::: warning
**⚠️ 常见误区**：MAC 的决策者是"管理员+安全级别"，不是资源所有者；RBAC 授权给"角色"而非具体个人——换人继承角色即继承权限。
:::

### 攻击 ↔ 防护 配对

| 攻击类型 | 防护措施 |
|---------|---------|
| SQL 注入 | **参数化查询**、输入过滤 |
| XSS | 输入过滤、输出编码 |
| CSRF | 令牌验证、Referer 检查 |
| 中间人攻击 | TLS 加密、**证书验证** |
| DoS/DDoS | 防火墙、流量清洗、**CDN** |

::: info
**🎯 一句话人话**：攻击题就是"攻击在干嘛 → 用什么招防"的配对题；另分被动（只偷看）和主动（动手改/破坏）两大类。
:::

::: tip
**💡 类比**：被动攻击像隔墙偷听（不动现场）；主动攻击像翻墙进屋搞破坏——动静大、更容易被发现。
:::

::: details ✍️ 小例子
**✍️ 小例子**：窃听/流量分析=被动攻击；DoS、SQL 注入、XSS、CSRF、中间人篡改=主动攻击。配对：SQL 注入→参数化查询；XSS→输出编码；CSRF→令牌验证；中间人→TLS+证书验证；DDoS→防火墙/流量清洗/CDN。
:::

::: warning
**⚠️ 常见误区**：XSS 与 SQL 注入都靠"输入"，但 XSS 是"在用户浏览器执行脚本"（防在输出编码）、SQL 注入是"骗数据库执行语句"（防在参数化）；CSRF 是"借你的身份发请求"，靠令牌/Referer 防。
:::

## 🧮 例题精讲

> 下面 4 道题覆盖本章必考点（对称 vs 非对称、数字签名、哈希长度、RSA）。先自己动手选一选、算一算，再看思路与逐步推演——考试时选择题也能快速锁定答案。

::: details 例题 1
**例题 1**：以下加密算法中，属于非对称加密的是：
- A. DES　B. 3DES　C. AES　D. RSA

**思路**：判断加/解密是不是"同一把钥匙"——对称加密用一把钥匙，非对称加密用"公钥+私钥"一对钥匙。

**逐步推演**：
1. DES、3DES、AES 都是对称算法：加密和解密用同一把密钥
2. RSA 是非对称算法的代表（基于大数分解），加密用公钥、解密用私钥
3. 四个选项里只有 D 是"公钥+私钥"的一对钥匙

**答案**：D（RSA）——与 Quiz 中 softdesigner-144 的答案一致。

**易错点**：① 别把 AES 当非对称——AES 是"对称加密里的现行标准"；② 别靠字母猜类别，RSA 是三位作者（Rivest-Shamir-Adleman）的名字缩写，不是算法性质的提示。

:::
::: details 例题 2
**例题 2**：数字签名的功能是：
- A. 加密数据　B. 验证发送方身份和数据完整性(不可否认性)　C. 压缩数据　D. 快速传输

**思路**：数字签名回答的是"是不是你发的、内容有没有被改"，回答不了"内容藏没藏起来"——签名和加密是两回事。

**逐步推演**：
1. 签名流程：发送方用私钥加密 Hash(消息) → 接收方用公钥解密验证
2. 私钥只有发送方持有 → 能验证发送方身份（身份认证）
3. 验证时哈希值比对不上 → 说明内容被改过（完整性）
4. 私钥不可抵赖 → 不可否认性
5. A（加密数据）是"保密"的活，C、D 与签名无关

**答案**：B——与 Quiz 中 softdesigner-157 的答案一致。

**易错点**：数字签名不提供保密性——消息是明文可见的，签名只是"盖私章"；"私钥签名、公钥验证"与"公钥加密、私钥解密"方向相反，别记混。

:::
::: details 例题 3
**例题 3**：SHA-256 哈希算法的输出长度为：
- A. 128 位　B. 160 位　C. 256 位　D. 512 位

**思路**：哈希算法名字里的数字就是输出位数——MD5=128、SHA-1=160、SHA-256=256。

**逐步推演**：
1. MD5 输出 128 位（已碰撞、不安全）
2. SHA-1 输出 160 位（已不安全）
3. SHA-256 输出 256 位——名字带 256，就是 256 位（64 个十六进制字符）
4. 输出 512 位的是 SHA-512，排除 D

**答案**：C（256 位）——自编题，与 quiz.json 无关，按本章"哈希算法输出长度速查"表核对。

**易错点**：① 把"输出长度"和 AES 的"密钥长度"混——AES-128 的 128 是密钥/分组长度，SHA-256 的 256 是输出长度；② 单位换算：256 位 = 32 字节，别把位当字节。

:::
::: details 例题 4
**例题 4**：RSA 算法中，取 p=3、q=11，公钥 e=3，则明文 m=5 加密后的密文 c 为：
- A. 15　B. 20　C. 26　D. 33

**思路**：RSA 加密公式 c = mᵉ mod n，先算模数 n = p×q，再把 m 的 e 次方对 n 取余。

**逐步推演**：
1. n = p × q = 3 × 11 = 33
2. c = 5³ mod 33 = 125 mod 33
3. 33 × 3 = 99，125 − 99 = 26 → c = 26

**答案**：C（26）——自编题，与 quiz.json 无关，手算复核（125 mod 33 = 26；且 26⁷ mod 33 = 5，能还原明文）。

**易错点**：① 密文是"m 的 e 次幂取余"，不是 e×m = 15（错选 A）；② 取余结果只能是 0~32，不可能等于 n=33（错选 D）；③ 若题目给 φ(n)=(p−1)(q−1)=20，还要求私钥 d 满足 e×d≡1 (mod 20)，即 3×7=21≡1，d=7——本题只问加密方向。

:::
